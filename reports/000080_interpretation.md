# E80: reserved-material intake stopped at TLS negotiation

The bounded native-label intake produced **0/4 raw post captures**. Its single
label-page attempt failed during TLS negotiation, before any HTTP application
response or page body was received. No candidate was nominated and no post request
was made. This is an acquisition feasibility failure, not evidence that suitable
Kamri posts are absent or that E79 fails to generalize.

E79's positive development result remains preserved and unconfirmed on genuinely
new reserved material. No new prediction, source identity, independent review,
semantic label or untouched unit is admitted. Semantic benchmark capacity remains
0/4 qualifying works; that separate requirement is not the four-slot intake budget.

## Registered route and budget

The [protocol](../experiments/reserved_intake_v80.md) and
[configuration](../experiments/reserved_intake_v80.json) were frozen before the
request. The exact Kamri label URL was already present as a rel=tag link in the
saved Western article. This supplied an observed route rather than an invented
feed endpoint or a new content-based search.

The intake allowed one label-page request, followed only on successful nomination
by up to four individual post requests. Selection would have used the first four
eligible article links in DOM order, with no topical or model-score preference,
replacement, pagination, alternate endpoint or client retry.

A frozen exposure registry contains **40 recorded same-host article keys** from
public tracked Markdown/JSON/Python files and four fixed local inventories.
Every screened file was snapshotted locally with its hash and the public commit
ID, so later README changes cannot alter replay. This is an incomplete recorded-
exposure screen, not proof of never-seen text or independent source groups.
No new candidates reached that screen during this run.


That establishes a TLS negotiation failure on this attempt. It does not identify
whether the cause lies in client compatibility, an intermediary or the remote
endpoint, and it is not an HTTP refusal, an empty label page or a robots-policy
finding. No unregistered diagnostic request was made to determine the cause.
The `no_challenge` flag is vacuously true for an absent body; it is not evidence
that a challenge-free page was obtained. The combined transport gate is false.

Intent, command, timestamps, headers, telemetry and stderr are retained locally.
The result preserves all four empty slots. The four unexercised post-request
opportunities cannot be reassigned to retries or other endpoints in E80.

## Stop and next resource decision

This closes E80 after its first-stage failure. No model scores were computed,
no prose was displayed, and no new raw post was admitted. E79's model, controls,
criteria and development result are unchanged. E62/E70 remain closed.

Before another research intake, transport capability needs to be established
independently of candidate content, or native saved captures need to be supplied
through a different documented resource. Any such infrastructure work/intake must
have a separately fixed scope and preserve this failed attempt. Do not silently
switch curl binaries, TLS settings, archive routes or browsing tools and report
the result as a successful E80 retry. Obtaining bytes would still leave grouping,
duplication, masking and confirmation eligibility unresolved.

No further requests or repeated model evaluation are launched by this report.

## Verification and preservation

A separate offline verifier, importing no E80 production functions, reconstructs
the exposure union, observed label link, command and budget, saved telemetry,
transport checks, empty selection and all four slots. It uses the same
BeautifulSoup HTML parser; this is independent accounting code, not independent
scientific review. All E79 sealed artifacts remain unchanged.

Six fixture tests cover strict URLs, exposure/duplicate/cap accounting, base tags,
identity conflicts, label/body ambiguity and transport/challenge failures.
**583 workspace tests and 544 isolated-public tests pass**, with the same 39
archive-dependent exclusions. Passing checks validate failure accounting, not
acquisition success. The verifier itself needs the excluded local archive:

```sh
.venv/bin/python scripts/verify_reserved_intake_v80.py
```

Public main contains code, protocol and small reports. Exposure snapshots and
network artifacts stay on the local-only evidence branch. Preparation and intake
are single-use and must not overwrite sealed output paths.
