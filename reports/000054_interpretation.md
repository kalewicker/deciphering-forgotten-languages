## Registered rule and preserved evidence

The [protocol](../experiments/offline_intake_v54.md), config and code/tests were
frozen before new decisions, with **150 input hashes**, all **53 prior run
manifests** and available deliverable seals. All five pages had already been
inspected. This is not a blind test of the revised rule and cannot demonstrate
improved generalization or accuracy. There were **zero network requests**,
searches, browser renders, messages or new acquisitions.

All scope, title, heading, date and topic decisions use the **original v42/v50
bytes**. E53 captures only replay current routing evidence; none replaces an old
body. Raw lengths/hashes match original receipts. Every E52 scope ledger is
reproduced exactly, retaining original body coordinates, paragraph owners/runs,
excluded structural channels, empty-owner inventories and accounting checks.

The rule makes three declared representation changes from E50:

- It requires agreement across HTML title, og:title and Article/NewsArticle
  JSON-LD headline. An h1 is optional; all present h1 values must match the same
  title. Multiple matching h1 elements are allowed. These fields share a response
  and do not constitute independent corroboration.
- Every canonical value must match the nominated URL. Every og:url must match
  directly or bind to an exact saved E53 redirect record whose five checks pass.
  Alias bindings are replayed from saved evidence; similar slugs are insufficient.
- Volume and topic checks use E52's uniform paragraph runs. The minima remain
  three nonempty units and 1000 characters, but run units replace direct-p units.
  Characters are summed over original spans, without between-run spaces. This
  is an explicit representation change, not an unchanged old denominator.

Complete transport/HTTP200, HTML markup, final URL, body/container identity,
challenge screening, whole-word topical terms and publication-date requirements
remain enforced. Only article:published_time supplies the date; all values must
parse and agree in **[2000-01-01, 2018-09-30]**. Modified dates, search snippets
and newly captured E53 dates cannot rescue an original failure.
